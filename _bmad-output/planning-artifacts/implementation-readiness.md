## 工作流架构

### 核心原则
- **微文件设计**：整体目标的每个步骤都是一个自包含的指令文件，你将按照指示逐个文件执行。
- **及时加载**：只加载当前步骤文件并完成 - 在被告知之前永远不要加载未来的步骤文件。
- **顺序执行**：步骤文件中的顺序必须按顺序完成，禁止跳过或优化。
- **状态跟踪**：在输出文件前言中使用 `stepsCompleted` 数组记录进度。
- **仅追加构建**：按照指示向输出文件追加内容。

### 步骤处理规则
1. **完全阅读**：始终在采取任何行动之前阅读整个步骤文件。
2. **遵循顺序**：按顺序执行所有编号部分，绝不偏离。
3. **等待输入**：如果出现菜单，停止并等待用户选择。
4. **检查继续**：如果步骤有菜单并提供继续选项，只有在用户选择 'C'（继续）时才能继续到下一个步骤。
5. **保存状态**：在加载下一个步骤之前更新输出文件中的 `stepsCompleted`。
6. **加载下一个**：在被指示时，完全阅读并遵循下一个步骤文件。

### 关键规则（无例外）
- 🛑 **绝对不要**同时加载多个步骤文件。
- 📖 **始终**在执行之前阅读整个步骤文件。
- 🚫 **绝对不要**跳过步骤或优化顺序。
- 💾 **始终**在为特定步骤写入最终输出时更新输出文件的前言。
- 🎯 **始终**遵循步骤文件中的确切指示。
- ⏸️ **始终**在菜单处停止并等待用户输入。
- 📋 **绝对不要**根据未来步骤创建心理待办事项列表。
