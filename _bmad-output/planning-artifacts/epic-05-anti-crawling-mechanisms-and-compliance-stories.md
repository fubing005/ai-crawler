# Epic 5: 反爬虫机制和合规 - Stories

## Epic 概述

**目标：** 用户系统自动处理反爬虫机制，遵守 robots.txt 和目标网站服务条款，确保法律合规。

**用户成果：**
- 自动请求频率控制
- User-Agent 和 IP 轮换
- 自动验证码处理
- 人类行为模拟
- 自动遵守 robots.txt
- 遵守 GDPR、CCPA、中国法律法规
- 数据采集前法律合规确认

**FRs 覆盖：** FR57-FR66, FR92-FR94

**技术备注：**
- 多层反爬虫策略
- 代理池配置
- 首次使用法律合规警告
- 数据本地存储和加密

**依赖关系：** Epic 4（需要爬取任务）

---

## Stories

### Story 5.1: 实施请求频率控制

作为系统，
我希望能够自动控制请求频率，
这样我就能避免触发目标网站的频率限制和反爬虫检测。

**Acceptance Criteria:**

**Given** 用户创建爬取任务
**When** 系统执行爬取
**Then** 系统在每次 HTTP 请求之间应用延迟
**And** 默认延迟设置为随机 2-5 秒
**And** 用户可以在任务配置中自定义延迟范围

**Given** 系统检测到 HTTP 429（Too Many Requests）错误
**When** 系统收到 429 错误响应
**Then** 系统自动增加请求延迟（例如：从 2-5 秒增加到 5-10 秒）
**And** 系统在日志中记录"检测到频率限制，已增加延迟"
**And** 系统继续重试请求

**Given** 用户配置了特定的频率控制
**When** 用户在任务设置中设置"最小延迟：3 秒，最大延迟：8 秒"
**Then** 系统使用用户指定的延迟范围
**And** 系统在请求之间随机选择延迟时间（在指定范围内）
**And** 系统在任务日志中记录实际延迟时间

**相关需求：** FR57（请求频率控制）

### Story 5.2: 轮换 User-Agent 字符串

作为系统，
我希望能够轮换 User-Agent 字符串，
这样我就能模拟不同的浏览器和设备，降低被检测为爬虫的风险。

**Acceptance Criteria:**

**Given** 系统发起 HTTP 请求
**When** 系统准备请求头
**Then** 系统从预定义的 User-Agent 池中随机选择一个
**And** User-Agent 池包含主流浏览器的常见 User-Agent 字符串
**And** 系统将选中的 User-Agent 添加到请求头

**Given** 系统爬取多个页面
**When** 系统发送连续请求
**Then** 每个请求使用不同的 User-Agent（尽可能）
**And** 系统避免短时间内重复使用相同的 User-Agent
**And** 系统在日志中记录每个请求使用的 User-Agent

**Given** 用户查看反爬虫设置
**When** 用户访问"User-Agent 配置"选项
**Then** 系统显示当前启用的 User-Agent 池
**And** 用户可以添加自定义 User-Agent 字符串
**And** 用户可以禁用或启用特定的 User-Agent

**相关需求：** FR58（User-Agent 字符串轮换）

### Story 5.3: 实施 IP 轮换和代理池

作为系统，
我希望能够轮换 IP 地址并使用代理池，
这样我就能避免因单一 IP 发起过多请求而被封禁。

**Acceptance Criteria:**

**Given** 用户配置了代理池
**When** 系统发起 HTTP 请求
**Then** 系统从代理池中随机选择一个代理
**And** 系统通过选中的代理发送请求
**And** 请求失败时，系统自动切换到下一个代理

**Given** 用户在系统设置中配置代理
**When** 用户添加代理到代理池
**Then** 用户可以输入代理地址和端口（例如：192.168.1.100:8080）
**And** 用户可以输入代理用户名和密码（如果需要认证）
**And** 系统测试代理可用性并显示状态

**Given** 系统使用代理发送请求
**When** 代理连接失败或超时
**Then** 系统标记该代理为"不可用"
**And** 系统自动切换到下一个可用代理
**And** 系统在日志中记录代理切换事件

**Given** 用户未配置代理池
**When** 系统发起 HTTP 请求
**Then** 系统使用系统默认网络连接
**And** 系统在设置中显示"未配置代理池，使用默认连接"提示
**And** 系统提示用户"为更好的反爬虫效果，建议配置代理池"

**相关需求：** FR59（IP 轮换和代理池）

### Story 5.4: 自动处理 CAPTCHA

作为系统，
我希望能够自动识别和处理 CAPTCHA（验证码），
这样我就能在遇到验证码时自动解决，无需人工干预。

**Acceptance Criteria:**

**Given** 系统访问网页
**When** 页面包含 CAPTCHA 挑战
**Then** 系统识别 CAPTCHA 类型（例如：reCAPTCHA、hCaptcha、文本验证码）
**Then** 系统启动 CAPTCHA 解决流程

**Given** 系统识别到文本验证码（图片验证码）
**When** 系统使用 OCR 或第三方服务解决验证码
**Then** 系统提取验证码图片
**And** 系统识别图片中的字符
**Then** 系统将识别的字符输入到验证码字段
**And** 系统提交表单

**Given** 系统识别到 reCAPTCHA 或 hCaptcha
**When** 系统使用第三方验证码解决服务（例如：2Captcha、Anti-Captcha）
**Then** 系统将验证码信息发送到解决服务
**And** 系统接收解决结果
**Then** 系统将结果注入到页面并提交
**And** 系统在日志中记录"CAPTCHA 已自动解决"

**Given** 系统多次尝试解决 CAPTCHA 都失败
**When** 失败次数超过阈值（例如：3 次）
**Then** 系统停止自动解决
**Then** 系统通知用户"无法自动解决 CAPTCHA，需要人工干预"
**And** 系统暂停任务并等待用户输入

**相关需求：** FR60（自动 CAPTCHA 处理）、FR64（90% 成功率）

### Story 5.5: 模拟人类行为

作为系统，
我希望能够模拟人类行为模式（随机延迟、鼠标移动、滚动），
这样我就能降低被检测为爬虫的风险，使爬取行为更像真实用户。

**Acceptance Criteria:**

**Given** 系统使用浏览器自动化（Playwright）
**When** 系统访问页面
**Then** 系统模拟人类导航行为
**And** 系统在页面加载后随机滚动（向下滚动 1-3 次）
**And** 系统在元素之间移动鼠标（随机路径）

**Given** 系统需要点击页面元素
**When** 系统准备点击
**Then** 系统将鼠标移动到元素位置（模拟真实路径，不是瞬间移动）
**Then** 系统在点击前随机等待 0.5-2 秒
**And** 系统执行点击操作

**Given** 系统在页面上停留
**When** 页面内容较长
**Then** 系统模拟向下滚动行为
**And** 滚动速度模拟人类阅读速度（每秒滚动 200-400 像素）
**Then** 系统在滚动中随机停顿（模拟阅读）

**Given** 用户查看反爬虫设置
**When** 用户访问"人类行为模拟"选项
**Then** 用户可以启用或禁用鼠标移动模拟
**And** 用户可以启用或禁用滚动模拟
**Then** 用户可以调整行为强度（低、中、高）

**相关需求：** FR61（人类行为模拟）

### Story 5.6: 支持动态加载的网站

作为系统，
我希望能够处理动态加载的内容（JavaScript 渲染），
这样我就能爬取使用 AJAX、React、Vue 等现代技术的网站。

**Acceptance Criteria:**

**Given** 用户爬取包含动态内容的网站
**When** 系统访问页面
**Then** 系统使用浏览器引擎（Playwright）完全加载页面
**And** 系统等待 JavaScript 执行完成
**Then** 系统等待动态内容加载（例如：等待特定元素出现）

**Given** 系统检测到页面使用 AJAX 或无限滚动
**When** 系统识别到"加载更多"按钮或滚动触发加载
**Then** 系统自动滚动到页面底部以触发更多内容加载
**Then** 系统等待新内容加载并提取
**And** 系统重复此过程直到所有内容加载完成

**Given** 用户配置爬取深度或时间限制
**When** 用户在任务设置中设置"最大爬取时间：5 分钟"
**Then** 系统在爬取动态内容时监控时间
**Then** 系统在达到时间限制后停止加载更多内容
**And** 系统在日志中记录"达到时间限制，停止加载"

**相关需求：** FR62（支持动态加载的网站）

### Story 5.7: 自动遵守 robots.txt 规则

作为系统，
我希望能够自动读取并遵守目标网站的 robots.txt 文件，
这样我就能尊重网站的爬取规则，避免法律风险和被封禁。

**Acceptance Criteria:**

**Given** 用户爬取新网站
**When** 系统开始爬取任务
**Then** 系统首先尝试获取目标网站的 robots.txt 文件（例如：https://example.com/robots.txt）
**And** 如果 robots.txt 存在，系统解析其中的规则

**Given** 系统解析 robots.txt 文件
**When** robots.txt 包含 User-agent 规则
**Then** 系统识别适用于本爬虫的规则
**And** 系统检查每个 URL 是否被 Disallow 规则禁止
**Then** 如果 URL 被禁止，系统跳过该 URL

**Given** 系统遇到被 robots.txt 禁止的 URL
**When** 系统尝试访问该 URL
**Then** 系统在日志中记录"URL 被 robots.txt 禁止，已跳过"
**And** 系统在任务报告中统计被跳过的 URL 数量

**Given** 系统找不到 robots.txt 文件
**When** 服务器返回 404 错误
**Then** 系统记录"未找到 robots.txt，将使用谨慎的爬取策略"
**Then** 系统应用保守的爬取设置（增加延迟、限制并发）

**相关需求：** FR63（遵守 robots.txt 规则）

### Story 5.8: 检测和响应 IP 封禁

作为系统，
我希望能够检测 IP 封禁或访问限制，
这样我就能及时调整策略并通知用户。

**Acceptance Criteria:**

**Given** 系统发送 HTTP 请求
**When** 服务器返回 403 Forbidden、429 Too Many Requests 或 503 Service Unavailable
**Then** 系统检测到可能的 IP 封禁或访问限制
**Then** 系统在日志中记录"检测到访问限制，响应码：XXX"

**Given** 系统检测到访问限制
**When** 系统配置了代理池
**Then** 系统自动切换到下一个代理 IP
**And** 系统增加请求延迟
**And** 系统重试请求

**Given** 系统检测到访问限制且未配置代理池
**When** 系统无法切换 IP
**Then** 系统暂停当前任务
**Then** 系统向用户显示警告："检测到 IP 可能被封禁，请配置代理池或稍后重试"
**And** 系统提供"配置代理"和"稍后重试"按钮

**Given** 系统持续收到访问限制响应
**When** 连续失败次数超过阈值（例如：10 次）
**Then** 系统标记任务为"失败"
**Then** 系统在任务报告中记录失败原因："IP 被封禁"
**And** 系统向用户发送失败通知

**相关需求：** FR66（检测和响应封禁尝试）

### Story 5.9: 配置反爬虫设置

作为用户，
我希望能够配置反爬虫机制的各种设置，
这样我就能根据不同网站的特点调整爬取策略。

**Acceptance Criteria:**

**Given** 用户在任务设置中
**When** 用户访问"反爬虫配置"部分
**Then** 系统显示所有反爬虫设置选项
**And** 选项包括：请求延迟、User-Agent 轮换、代理池、CAPTCHA 处理、人类行为模拟

**Given** 用户配置请求延迟
**When** 用户在"请求延迟"设置中
**Then** 用户可以设置最小延迟和最大延迟
**And** 用户可以选择延迟模式：固定、随机、指数退避
**Then** 系统提供延迟强度滑块（保守、标准、激进）

**Given** 用户配置 User-Agent 轮换
**When** 用户在"User-Agent"设置中
**Then** 用户可以启用或禁用 User-Agent 轮换
**And** 用户可以查看和编辑 User-Agent 池
**Then** 用户可以添加自定义 User-Agent

**Given** 用户配置代理池
**When** 用户在"代理池"设置中
**Then** 用户可以添加、编辑、删除代理
**And** 用户可以测试代理连接性
**Then** 用户可以设置代理轮换策略：随机、轮询

**Given** 用户配置 CAPTCHA 处理
**When** 用户在"CAPTCHA"设置中
**Then** 用户可以选择 CAPTCHA 解决服务（2Captcha、Anti-Captcha 等）
**Then** 用户可以输入 API Key（如果服务需要）
**And** 用户可以设置最大尝试次数和超时时间

**相关需求：** FR65（配置反爬虫设置）

### Story 5.10: 法律合规警告和确认

作为用户，
我希望在首次使用系统时看到法律合规警告，
这样我就能了解数据采集的法律要求并确保合规操作。

**Acceptance Criteria:**

**Given** 用户首次启动应用
**When** 用户完成初始设置
**Then** 系统显示法律合规警告对话框
**And** 对话框包含法律合规提示文本

**Given** 系统显示法律合规警告对话框
**When** 对话框内容显示
**Then** 提示文本包括：GDPR 合规性要求、CCPA 合规性要求、中国网络安全法要求
**And** 提示文本说明："请确保您有权爬取目标网站的数据"
**And** 提示文本说明："请遵守目标网站的 robots.txt 和服务条款"

**Given** 用户阅读法律合规警告
**When** 用户继续操作
**Then** 系统显示"我已了解并同意遵守法律要求"复选框
**And** 用户必须勾选复选框才能继续
**Then** 系统保存用户确认（不再显示警告）

**Given** 用户创建新的爬取任务
**When** 用户输入目标网址
**Then** 系统在任务创建向导中显示法律合规提示
**And** 提示："请确认您有权爬取此网站的数据并遵守其服务条款"
**And** 系统提供"目标网站服务条款"链接（如果可用）

**相关需求：** FR92（GDPR 合规）、FR93（CCPA 合规）、FR94（中国网络安全法合规）
